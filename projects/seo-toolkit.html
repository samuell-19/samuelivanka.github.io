Case Study

Programmatic SEO Toolkit Programmatisk SEO Toolkit

A Python-based toolkit that automates four technical SEO tasks: entity extraction, content gap analysis, schema markup auditing, and GSC-enriched internal linking.

Et Python-baseret toolkit, der automatiserer fire tekniske SEO-opgaver: entitets-ekstraktion, content gap-analyse, auditering af schema-markup og GSC-beriget intern linkning.

The project was built to demonstrate practical understanding of how Google processes and evaluates web content, going beyond keyword-level optimisation to work at the entity and knowledge graph level (the layer that increasingly determines ranking outcomes).

Projektet er udviklet for at demonstrere en praktisk forståelse af, hvordan Google processerer og evaluerer webindhold. Det går skridtet videre end blot søgeordsoptimering ved at arbejde på entitets- og Knowledge Graph-niveau (det lag, der i stigende grad afgør placeringerne i søgeresultaterne).

This project targets iGaming industry, but can be obviously, with minor adjustments, used for any other industry.

Projektet er målrettet iGaming-industrien, men kan selvfølgelig, med minimale justeringer, overføres til enhver anden branche.

Why I built it Hvorfor jeg byggede det

Google has been shifting from keyword matching to entity understanding since the Hummingbird update (2013) and accelerating with MUM and Gemini integrations. Tools that operate at the keyword level are increasingly insufficient for competitive SEO. This toolkit operates at the entity level — the same layer Google uses internally.

Siden Hummingbird-opdateringen (2013)har Google rykket sig fra søgeords-matching til entitets-forståelse. En udvikling, der er accelereret yderligere med MUM og Gemini-integrationer. Værktøjer, der kun opererer på søgeordsniveau, bliver i stigende grad utilstrækkelige i moderne, kompetitiv SEO. Dette toolkit arbejder på entitetsniveau – det samme lag, som Google selv bruger internt.

How it works Sådan fungerer det

The pipeline Pipelinen

01
Entity Extractor
main.py

Crawls the target site with headless Chromium (via Playwright), extracts fully-rendered page text, and sends it to Google's Natural Language API. Returns named entities with salience scores — the same signals Google uses to understand your content.

Crawler målsitet med headless Chromium (via Playwright), udtrækker fuldt renderet sidetekst og sender den til Googles Natural Language API. Returnerer navngivne entiteter med salience scores — de samme signaler Google bruger til at forstå dit indhold.

Input Target domain URL
API Google Natural Language API · Playwright / Chromium
Output entity_report.csv
02
Gap Analyser
gap_analyser.py

Compares the site's entity profile against a pre-built master entity list of 80+ entities for the casino vertical. Flags missing entities and those that are under-represented by salience score — identifying exactly where topical authority is thin.

Sammenligner sitets entitetsprofil med en præbygget master-entitetsliste med 80+ entiteter for casino-vertikalen. Markerer manglende entiteter og dem der er underrepræsenteret ud fra salience score — og identificerer præcis hvor tematisk autoritet er svag.

Input entity_report.csv · master entity list (80+ casino entities)
API —
Output gap_report.csv
03
Schema Generator
schema_generator.py

Audits existing JSON-LD on each page, detects page type, and generates ready-to-paste schema markup with correct ordering — WebSite and Organization first, supporting types after. Google reads the first schema as the primary identity signal for that page.

Auditerer eksisterende JSON-LD på hver side, registrerer sidetype og genererer schema markup klar til indsætning med korrekt rækkefølge — WebSite og Organization først, understøttende typer bagefter. Google læser det første schema som det primære identitetssignal for siden.

Input Crawled page source (Playwright) · entity_report.csv
API —
Output schema_recommendations.csv
04
GSC Internal Linking
gsc_connector.py

Pulls 90 days of Google Search Console data via OAuth 2.0. Identifies pages ranking in positions 8–20 (page 2) as priority internal link targets — the pages closest to ranking on page 1. Uses real GSC queries as anchor text recommendations.

Henter 90 dages Google Search Console-data via OAuth 2.0. Identificerer sider der rangerer i position 8–20 (side 2) som prioriterede interne link-mål — de sider der er tættest på at rangere på side 1. Bruger rigtige GSC-forespørgsler som ankertekst-anbefalinger.

Input Target domain · OAuth credentials · gap_report.csv
API Google Search Console API (OAuth 2.0)
Output gsc_internal_links.csv

Why it works the way it does Hvorfor det fungerer som det gør

Why Playwright, not requests? Hvorfor Playwright, ikke requests?

Most casino sites render content via JavaScript. A standard HTTP request returns only the HTML shell — not what Google or users actually see. Playwright launches a real Chromium browser and extracts fully-rendered page text. Same content, same extraction.

De fleste casino-sites renderer indhold via JavaScript. En standard HTTP-forespørgsel returnerer kun HTML-skallen — ikke hvad Google eller brugere faktisk ser. Playwright starter en rigtig Chromium-browser og udtrækker fuldt renderet sidetekst. Samme indhold, samme udtrækning.

Why Google's own NLP API? Hvorfor Googles egen NLP API?

Strategic choice. Google uses this same infrastructure to process web content. Optimising for the entities it returns means optimising for the signals Google actually uses — not a proxy for them.

Strategisk valg. Google bruger denne samme infrastruktur til at behandle webindhold. Optimering for de entiteter den returnerer betyder optimering for de signaler Google faktisk bruger — ikke en proxy for dem.

Why a pre-built entity list for gap analysis? Hvorfor en præbygget entitetsliste til gap-analyse?

The original design crawled competitors. It failed — geo-blocking and bot protection are aggressive in iGaming. The pre-built list is based on Google's Knowledge Graph associations for the casino vertical globally. More robust, no crawling infrastructure needed.

Det oprindelige design crawlede konkurrenter. Det mislykkedes — geo-blokering og bot-beskyttelse er aggressiv i iGaming. Den præbyggede liste er baseret på Googles Knowledge Graph-associationer for casino-vertikalen globalt. Mere robust, ingen crawling-infrastruktur nødvendig.

Why does schema order matter? Hvorfor er schema-rækkefølge vigtig?

Google treats the first schema on a page as the primary signal for that page's identity. A homepage that leads with an Offer schema signals "this page is a promotional offer" — not "this is a brand." The toolkit enforces WebSite → Organization first, always.

Google behandler det første schema på en side som det primære signal for sidens identitet. En hjemmeside der starter med et Offer-schema signalerer "denne side er et tilbud" — ikke "dette er et brand." Toolkittet håndhæver WebSite → Organization først, altid.

Limitations Begrænsninger

What it doesn't do (yet) Hvad det ikke gør (endnu)

The internal linking tool works best with 50+ crawled pages — at 30 pages the entity co-occurrence data is shallow. There's no search volume integration, so gap analysis prioritises by topical completeness rather than traffic opportunity. Schema auditing can't verify whether field values are accurate, only whether they exist. These are known limitations, not surprises — and they point directly to the next layer of development.

Internt linking-værktøjet fungerer bedst med 50+ crawlede sider — ved 30 sider er entitets-co-occurrence-dataen overfladisk. Der er ingen søgevolumenintegration, så gap-analyse prioriterer efter tematisk fuldstændighed frem for trafikmulighed. Schema-audittering kan ikke verificere om feltværdier er nøjagtige, kun om de eksisterer. Dette er kendte begrænsninger, ikke overraskelser — og de peger direkte mod næste udviklingslag.
